## 2. Setting up the laptop

```
git clone git@github.com:JohnSmall/it-from-bit-2026.git
cd it-from-bit-2026
latexmk paper1/main.tex
```

That should finish with `Output written on main.pdf`. A build is clean only if
`grep -E '^!' paper1/main.log` returns nothing.

Needs TeX Live 2025 with `biber`. `texlive.profile` is the answer file that
produced the desktop installation, so `install-tl --profile texlive.profile`
reproduces it.

The agent will ask who you are on first run, because `CONTRIBUTOR.md` is
gitignored and does not travel. That is by design.

For the notebooks, rebuild the environment from `notebooks/README.md`; `.venv`
is 686 MB and is not in the repository.

## 4. The bibliography, which is the one real friction

`paper1/references.bib` is tracked and current at 341 entries, so the laptop
builds. But it is **generated** by Better BibTeX from Zotero, and the
auto-export that regenerates it is registered against an absolute path on the
desktop. On the laptop it is a static input until you set that up again:

1. Install Better BibTeX in the laptop's Zotero.
2. Right-click the `self-ref-2026-cited` collection, Export Collection,
   format Better BibLaTeX, tick **Keep updated**.
3. Save over the clone's `paper1/references.bib`.

The desktop's export delay is 69 seconds, debounced: every change restarts the
countdown, so a batch of edits produces one export once you stop.

**Citation keys survive the move.** All 1,539 live in Zotero's own
`citationKey` field, not in a Better BibTeX side database, so they sync as
ordinary item data. This was checked explicitly, because had they been pinned
only locally the laptop would have regenerated different keys and broken every
`\autocite` in the paper.

## 6. Why the tag is a snapshot and not `paper1-v2`

The paper's colophon still reads Version 0.5, unchanged since `paper1-v1`, and
the Zenodo sequence has not run. `snapshot-2026-10-26` marks the handover point
without claiming a release. The tag message records the known undefined
reference so it is not mistaken for a regression later.

## 7. Backups on the desktop

`~/Zotero-backup-2026-10-26`, 1.1 GB, taken with Zotero closed and verified:
`integrity_check` and `foreign_key_check` both pass, and the item, citation-key,
collection, attachment, creator and tag counts all equal the live library. It
includes `_profile/`, the Zotero profile with `prefs.js` and the Better BibTeX
auto-export registration, which lives outside the Zotero data directory and is
easy to miss. Its own `README-BACKUP.txt` says how to restore.

It sits on the same disk as the original, so it protects against a bad sync but
not against losing the drive.

## 8. Conventions worth re-reading before editing

`CLAUDE.md` is the behaviour contract and binds people as well as agents. The
points most easily forgotten after a break:

- `.tex` edits go through a sentinel-gated patch script in `scripts/` that
  asserts its anchors match exactly once, writes a `.bak`, adds an
  `% EDITED <date>` header and refuses to run twice.
- Never edit `paper1/references.bib` by hand; it is generated.
- Every claim carries exactly one of six status labels, never upgraded in
  place. Propose; the maintainer applies.
- Read `knowledge/invalid_routes.md` before proposing any mechanism or mass
  route.
- Stage by path. A `git add -A` on 2026-10-19 swept a private letter into the
  index; it was caught before it was committed.
