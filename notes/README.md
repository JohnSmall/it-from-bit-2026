# notes/

Working state: things to do, and things to think about later. Deliberately
separate from `knowledge/`.

The distinction matters because `CLAUDE.md` gives `knowledge/` a consult
order, and an assistant reading for established results should not have to
wade through chores.

| where | what belongs there |
|---|---|
| `knowledge/results_ledger.md` | claims, each carrying one status label |
| `knowledge/open_problems.md` | formal open problems with PASS/FAIL criteria |
| `knowledge/invalid_routes.md` | routes tried and failed; never retry |
| `knowledge/sessions/` | dated record of what a session actually did |
| `notes/todo.md` | actionable chores, with enough context to act |
| `notes/ideas.md` | follow-ups not yet actionable or not yet formed |

Nothing here carries a status label. An idea that hardens into a claim moves
to the ledger and acquires one there; an idea that hardens into a problem
with criteria moves to `open_problems.md`. Items here are working notes and
should be deleted when done rather than accumulating a graveyard of ticks.
